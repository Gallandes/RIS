## Как запустить
Нужны Docker и Docker Compose (см. ЛР0).

```bash
cp .env.example .env        # если .env ещё нет; задайте пароль
docker compose up --build -d
docker compose ps
curl -s http://127.0.0.1:8080/health          # → {"status": "ok"}
curl -s http://127.0.0.1:8080/api/v1/info
docker compose logs -f api                    # журнал в формате JSON Lines
docker compose down                           # остановить (данные базы сохранятся)
```

## Как устроен репозиторий

## Что уже сделано в заглушке для безопасности
- процесс в контейнере работает от пользователя `appuser`, а не `root`;
- файловая система контейнера только для чтения, привилегии ядра сброшены (`cap_drop: ALL`);
- порт API открыт только на `127.0.0.1`, порт базы не публикуется совсем;
- пароль базы — в `.env`, который не попадает в Git;
- ответ об ошибке не раскрывает внутреннее устройство, заголовок `Server` без версий.

Типы событий журнала `data.read` и `http.not_found` в заглушке — примеры; если они нужны району, предложите их в словарь Р4 через архитектурный совет.

## Работа с Git без сервера
```bash
git switch -c feature/dfd        # работа в отдельной ветке
git add -A && git commit -m "DFD района v0"
git switch main && git merge feature/dfd
scripts/pack.sh                  # out/d8-soc-ДАТА.zip и .bundle
git clone out/d8-soc-ДАТА.bundle копия   # так коллега получает всю историю
git pull ../путь/к/файлу.bundle main            # подтянуть изменения из присланного bundle
```
