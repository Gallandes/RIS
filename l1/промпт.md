# Л1 — единый промпт (район 8, Городской SOC)

Копировать целиком, одинаково во все модели. Ничего не менять. Если модель ответила по-английски — второй строкой дописать «Отвечай только на русском языке» и отметить это в `сравнение.md`.

```
Ты — инженер по безопасности. Составь черновик модели угроз
по методике STRIDE для сервиса, описанного ниже.

ОПИСАНИЕ СЕРВИСА:
Центр мониторинга: собирает журналы всех районов (JSON Lines), хранит их, ищет признаки атак, показывает дашборды; проверки безопасности в CI. Получает city.grid.alarm.raised.v1, публикует city.soc.incident.opened.v1.
Наше решение: сервис collector (Fluent Bit) принимает журналы районов и алерты IDS Suricata и пишет их в OpenSearch и в отдельный архив только на дозапись; дашборды OpenSearch Dashboards для аналитиков. Сервис api на Python с базой PostgreSQL ведёт инциденты и статус источников (какой район давно не присылал журналы). Роли: аналитик SOC, старший аналитик, администратор SOC; в CI для репозиториев районов запускаются Trivy, Semgrep и gitleaks.

ОБЩИЕ ПРАВИЛА ГОРОДА: пользователи входят через единый вход
Паспортного стола; районы обмениваются событиями через шину
Транспорта; журналы в формате JSON уходят в Городской SOC;
весь внешний трафик идёт через Шлюз.

ЧТО НУЖНО:
1. Перечисли 5-8 элементов схемы потоков данных (DFD):
   внешние участники, процессы, хранилища, потоки.
2. Для каждого элемента — угрозы по STRIDE (S, T, R, I, D, E)
   в виде таблицы: элемент | буква STRIDE | угроза (конкретно,
   1 предложение) | мера защиты (1 предложение).
   Если класс угроз к элементу неприменим — пропусти его.
3. Назови 3 самые опасные угрозы и объясни выбор.
Пиши конкретно для этого сервиса, без общих фраз.
Если чего-то не знаешь о сервисе — так и напиши, не выдумывай.
```
